# Layout + polysilicon scripting: field feedback for the engine team

Author: the agent that built `waveform-generator`'s analog macro. Audience:
the RocketEngine team. Tone: blunt on purpose — everything below cost me
real debugging hours. All paths are repo-relative to `waveform-generator/`
unless noted; every claim cites the file that proves it.

Related prior review: the RocketEngine API contract review (chat, 2026-11-03),
which covered the schematic/sim side. This doc covers layout only: what I
drew, how, with what, what broke, and what the engine must provide.

## 0. TL;DR — the five verdicts

1. **Provisioning is the worst part.** The engine venv cannot build the
   PCells (`sky130==1.0.0` needs `gdsfactory~=9.40.1`, engine ships
   `>=9.51`). I hand-rolled a second venv in `/tmp`. If the engine
   provisions toolchains, version-compat is its job, not mine.
2. **Schematic and layout disagree on device identity** and nothing checks
   it: sim runs `res_high_po`, layout draws `res_generic_po`. Same drawn
   lengths, different PDK device. LVS is still pending, so this is an open
   modeling risk, not a closed loop.
3. **Electrical values are mirror-by-comment, not single-sourced.** Lengths
   are duplicated as literals in two generators; the comments already
   disagree (`rsheet` 1112.4 vs 317.39, W=10 vs W=20 TGs). Drift has started.
4. **Magic's scars must be encoded, not documented.** Import order, unit
   discipline (100/um vs 200/um internal), `load`-vs-`create`, a segfaulting
   DRC subcommand — my runbook (`docs/magic_stitch.md`) lists six ways raw
   Magic silently does the wrong thing with exit code 0. A passthrough
   wrapper re-burns every user.
5. **The stack is viable.** gdsfactory PCells + Magic DRC + klayout region
   checks + LibreLane macro produced a DRC-clean R-2R macro that simulates.
   Every gap below is at a seam, not in any single tool.

## 1. What I built

`design/analog/gds/r2r_dac8_macro.gds`, generated by
`scripts/gen_analog_layout.py` (209 lines), mirroring
`scripts/gen_analog_pdk.py` (215 lines, the xschem schematic source).

| Block | PCell / geometry | Params | Count |
|---|---|---|---|
| Shunt 2R legs | `sky130.pcells.sky130_fd_pr__res_generic_po` | W=4, L=179.245 (R2_LEN/4) | 8 cols × 4 legs = 32 |
| Series R legs | same PCell | W=4, L=178.715 (R_LEN/2) | 7 cols × 2 legs = 14 |
| Filter resistor | same PCell | W=1, L=89.36 | 1 |
| Filter cap | `sky130.pcells.sky130_fd_pr__cap_mim_m3_1` | 15×15 | 1 |
| Trunk/straps/drops | hand polygons on met1 | — | ~40 rects |
| Via stacks m1→m4 | hand cut arrays + pads | LEF-transcribed rules | 2 stacks |
| Pins | anonymous 6×6 met1 pads, **no text** | — | vout, D7..D0, vref, vgnd, fout |

Layers touched directly: met1–met4 drawing, via/via2/via3 drawing.
Layers touched via PCells (opaque to me): poly, diffusion, contact, implant,
m1–m4 inside the resistor and MiM cells. Resistor ports used: `PLUS`/`MINUS`
(found by printing `ports`, not from docs). Cap ports: never queried — the
stack lands by arithmetic next to the cap body.

Ratio design (the actual analog engineering): 2R length 716.98 vs 2×357.43 =
714.86 — deliberately unequal to absorb the ~590 Ω end-contact term so the
**ratio** is exactly 2.000 (literal 2× length gives 1.894). TG switches are
W=20 (Ron lesson: 0.2–1 kΩ single-sided left 45 mV MSB error at 10 kΩ;
W=20 parts drop it to ~2 mV).

- xschem 3.4.7/3.4.8RC, ngspice-42, klayout (`klayout.db` Python API in
  `verify_stitch.py`), LibreLane via AppRun squashfs (`/tmp/llex`), yosys.

## 3. How I scripted it (the patterns that worked)

- **One topology, two emitters — by hand.** `gen_analog_pdk.py` emits the
  `.sch`, `gen_analog_layout.py` emits the `.gds`. They share nothing but a
  comment saying "values mirror …". It worked (lengths match today) and it
  is already drifting (see S3). The discipline held because both files are
  short and I diffed them by eye.
- **Folded columns + straps, not placed routes.** Each R-2R column is N
  parallel PCell legs (`LEG_PITCH = 10.0`) with met1 straps top and bottom;
  series nodes join a segmented trunk (`build_trunk`, one segment per node —
  spanning two nodes would short the rung, commented at the call site).
  All coordinates are closed-form arithmetic from `R_LEN`/`R2_LEN`, so the
  whole field re-folds if a length changes. This is the one part I would
  keep exactly as-is.
- **Hand-rolled via stacks.** `via_stack()` builds 2×2 cut arrays + landing
  pads from `VIA_RULE`, a dict I transcribed from the LEF
  `M1M2_PR/M2M3_PR/M3M4_PR GENERATE` rules (cut 0.15/0.20, pitch, enclosure
  as bare floats). `up_stack()` chains m1→m4. It DRCs clean, and it is a
  liability: nothing ties those floats to the PDK revision.
- **Magic driven by generated Tcl, verified twice.** `gen_stitch.py` parses
  the LibreLane LEF, asserts overlap-with-own-pin and clearance **in
  Python**, then emits `results/stitch.tcl`; `make stitch` pipes it into
  `magic -dnull -noconsole`. Then `verify_stitch.py` re-checks every strap
  against ALL macro metal with klayout regions — because Magic DRC cannot
  see same-layer shorts (overlap reads as connection, never violation).
  The two checkers are deliberately independent implementations.
- **Headless rendering as ground truth.** `plot_gds.py` renders GDS without
  a display; the plot once caught wires at 2× scale with a vacuous DRC 0
  (see S6). Screenshots are load-bearing verification here, not decoration.

## 4. Scars — what hurt, with evidence

**S1. Provisioning: two venvs, one `/tmp` hack.** The engine venv cannot
import the PDK PCell package at a compatible version, so layout runs from
`/tmp/gfsky130` — outside the repo, outside version control, unmirrored in
CI. If the ChatGPT brief pasted into this project holds (`sky130==1.0.0`
declares `gdsfactory~=9.48`), then even 9.40.1 is off-label and the engine
is shipping a combination it never tested. Either way: toolchain
compatibility is engine business. I should never `pip install` around the
engine to use the engine's own PDK flow.

**S2. Schematic sim device ≠ layout device.** The schematic instantiates
`sky130_fd_pr/res_high_po.sym` with `model=res_high_po`; the layout places
`sky130_fd_pr__res_generic_po` PCells. Drawn lengths match (357.43/716.98
in both files — verified by reading), so ratios match, but device identity
does not, and LVS is still pending. If `generic_po` and `high_po` are the
same physical resistor this is paperwork; if not, my passing DNL proves
nothing about the GDS. Nobody — human or engine — currently asserts
sch-model ↔ layout-PCell correspondence.

**S3. Mirror-by-comment is already drifting.** `gen_analog_pdk.py` says
`rsheet=1112.4`, `R=100k`, "TG Ron ~70R via W=10 FETs"; the instances say
W=20 and `gen_analog_layout.py` says `rsheet 317.39`, `R~28.3k`. Lengths
still agree, but three numbers around them have rotted in one revision
flat. Absolute-R truth is therefore unknown (pending PEX-vs-schematic
check); only ratios are verified. Lengths must live in ONE place.

**S4. Via rules are magic numbers.** `VIA_RULE` in `gen_analog_layout.py`
is a hand copy of LEF GENERATE data. A PDK point-release changes a pitch
and nothing fails loudly — DRC stays green until it doesn't, on someone
else's design. I needed a queryable rule table; I had `grep`.

**S5. Text purposes: `label()` is a no-op.** GDS text choked Magic input,
so pin naming is a `pass` and pins are anonymous met1 squares
(`gen_analog_layout.py:41-48`). Pin *function* currently travels by
convention (pad coordinates both sides agree on). Magic, KLayout, and
LibreLane each treat text purposes differently and nothing in my flow
states the contract. Whoever owns `layout.map_pins` must also own the
text-purpose table per backend, or pin names will keep living in comments.

**S6. Magic: six silent footguns, all with exit code 0.**
(`docs/magic_stitch.md`, each probe-verified.)
1. Import order: GDS **before** LEF, or 437 "already existed" warnings.
2. `cellname create` doesn't reliably switch cells — paint lands in the
   imported macro and `save` dies on its read-only timestamp. `load`
   creates-or-switches deterministically.
3. Units: typed boxes are 100/um; imported GDS lives at 200/um internally.
   Painting at ×200 puts wires at 2× scale, floating in space, with a
   **vacuous DRC 0**. Only the screenshot caught it.
4. Bare `drc listall` segfaults 8.3.685. (`drc listall why` is safe.)
5. No air wires: stitching means computing strap geometry from LEF pins in
   Python and asserting before painting. The tool gives no affordance.
6. `gds write` needs an absolute path (cwd differs between recipe and run).
A wrapper that passes user geometry straight through to Magic re-burns
every user on at least #3 (green check, wrong chip).

**S7. PEX is half-manual.** `scripts/extract_top.tcl` is committed and the
post-`top_pex.spice` flow is scripted (`make pex`: bracket-sed, per-mode
tb gen, ngspice, `check_pex.py`), but running the extraction itself is
documented as "interactive Magic". Device-mapping the PDK ladder for
extraction is still on my todo list. Until `run_extraction` covers Magic
`ext2spice` end-to-end **including the device map**, analog PEX stays
artisanal and unrepeatable in CI.

**S8. PCell API opacity.** Working facts I earned by trial, none from docs:
resistor ports are `PLUS`/`MINUS`; params are `res_width`/`res_length`
(schematic says `W`/`L`); the cap got placed with zero port queries (stack
lands by arithmetic); guard rings were never considered (the ChatGPT brief
mentions `guard_ring=True` — my 46 resistor legs have none, and no checker
complained; latch-up correctness is therefore unknown, not verified).
DRC-clean-by-construction guidance does not exist; I DRC-and-prayed once
and got lucky on rev1.

**S9. No sch↔layout co-check exists.** `pdk_dac_sweep.py` asserts 66 `X`
instances in the netlist; nothing asserts `sch(L) == layout(res_length)`
or `sch(model) == layout(pcell)`. FET-level LVS (pending) covers
transistors, not this. My lengths match because I read two files in one
afternoon. That is not a process.

## 5. Where Rocket would have helped (scar → leaf, honestly graded)

| Scar | Closest new-API leaf | Grade + what's missing |
|---|---|---|
| S1 provisioning | `system.get_capabilities / check_capability / get_resolved_config`, `ip_*` versioned | C — needs a real compat matrix (PDK rev × tool versions), a venv manager, and resolved-config echoed in every run answer, not a separate call I must remember |
| S2/S9 device + param correspondence | `project.*` entities, `run_lvs`, `run_view_sync`, `get_findings` | D — LVS covers FETs, not sch-model↔layout-PCell identity or `sch(L)==layout(res_length)`. Needs a named check kind (e.g. `param_sync`) or a single-topology object that emits both |
| S3 single source | `project.create_entity / set_component`, `apply_mutations` | B — the shape is right (one topology object → sch + gds + sim deck), but nothing today generates all three or forbids mirror-by-comment |
| S4 via rules | `layout.bind_layers / list_layers / get_layer_stackup / get_layer_rows / *_layer_preset` | B — if `get_layer_rows` returns cut/pitch/enclosure per via level, my `VIA_RULE` dict dies. If presets are only metal widths, it doesn't. Needs a via-stack **generator**, not just presets |
| S5 text/pins | `layout.map_pins`, `layout.serve_asset` | C — pin mapping without a per-backend text-purpose contract just moves the no-op into the engine. State the table: what text purposes Magic/KLayout/LibreLane read and write |
| S6 Magic footguns | any `layout.*`/`simulate.run_drc` wrapper over Magic | F as passthrough, A if encoded — import order, unit discipline (assert 100/um at the boundary), `load`-not-`create`, crash-guard on `drc listall`. Each of my six is a test case; ship them as such |
| S7 PEX | `simulate.run_extraction`, `run_post_layout` | C — must cover Magic `ext2spice` end-to-end **including the device map** for custom poly, else analog PEX stays artisanal |
| S8 PCells | `ip_search / ip_get / ip_instantiate`, `layout.place_cell` | C — needs queryable param schemas, port lists, per-cell DRC footnotes, and guard-ring guidance. `place_cell` without that is a prettier footgun |
| Stitch verify pattern | `run_erc / run_connectivity / run_view_sync` | B — my klayout second-opinion (shorts DRC can't see) is exactly the species these should cover; name the check kinds so I can tell |

## 6. What I wish existed (prioritized, concrete)

- **W1. `pdk.resolve`.** One call: PDK rev × tool-compat matrix, venv
  recipe, layer/via rule tables machine-readable. Kills S1 and S4 together.
- **W2. One topology → three emitters, or one equivalence check.** Either
  generate sch+gds+sim-deck from a single object, or ship `param_sync`
  (S2/S3/S9). Generating two files from one comment thread is not a flow.
- **W3. PCell browser as API.** Params, ports, DRC footnotes, guard-ring
  policy per cell, queryable (S8). I found `PLUS`/`MINUS` with a print
  statement; that is embarrassing for all of us.
- **W4. Magic runbook as code.** Import order, unit asserts, crash guards
  (S6). My six footguns are your regression tests — take them.
- **W5. Text-purpose contract per backend** (S5). A table, enforced at
  GDS write/read boundaries, with pin-name round-trip tests.
- **W6. Shipped construction helpers, not raw polygons.** Strap, trunk,
  via-stack, pad-with-label as engine primitives (my `m1`/`via_stack`/
  `up_stack`/`pin_pad` hand-rolled in 60 lines — that file should not need
  to exist).
- **W7. Console escape with env parity + artifact write-back.** Restating
  the prior review's verdict because layout is where it bites hardest:
  every seam above was crossed with Python + shell, and the only thing
  that kept it honest was my own `/tmp`-vs-`results/` discipline. The
  engine should provide that discipline (and `project.rewind` as the undo).

## 7. Closing credit (what worked — keep it)

The gdsfactory+sky130 PCell path **does** produce a DRC-clean analog macro;
Magic batch mode **is** scriptable once the runbook is known; klayout
region checks caught what DRC structurally cannot; the LibreLane digital
macro dropped into the stitch flow without drama. The toolchain is viable
end to end. All nine scars are seams, provisioning, and honesty gaps —
exactly the things an engine exists to own. Own them.
